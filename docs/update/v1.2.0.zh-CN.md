# Prism ROS Adapter v1.2.0

本次将 ROS Adapter 升级到 **Prism-SDK 1.2.0 / Runtime API 18**，面向
**Agent 1.2.0 + Sensor Board 0.4.27**。这是包含 ROS 接口变更的升级，旧工程
需要重新编译消息和服务，不要混用 1.1.0 的生成代码或 SDK 库。

## SDK 后台升级接口同步

- Host 与 RK-local SDK 统一固定到 `970043c94131ab04f7e2f8de5267012785e4d1fd`，更新头文件、二进制库及发布包，重新验证 USB 和 RK-local 构建。
- SDK 新增 `startSensorBoardUpdate()`、`sensorBoardUpdateStatus()`，用于 Agent 管理的 Sensor Board 后台升级。本次仅同步依赖，**ROS 不新增固件升级服务或话题**，现有 ROS 接口不变。
- 保留校时心跳及时间采样修复，版本继续为 1.2.0 / Runtime API 18，Linux glibc 基线仍为 2.31。
- 已安装的 ROS 工作空间和 Docker 镜像需重新构建，旧二进制不会自动获得新版 SDK；仍不提供离线数据集下载功能。
- 匹配 Agent：`3380718`；SDK 后台升级接口来源：`21c09ae`。本次不自动升级设备。

## USB 校时心跳修复

- 更新匹配的 Host SDK：空闲校时成功或异常退出后保持 USB 心跳工作，避免随后开始采集
  因心跳线程退出而停止，不再需要为恢复这一异常而断开重连。
- 校时错误仍如实上报；采集超时保护、ROS 接口及 ABI 不变，也不新增离线数据集下载。
- RK-local/Web 使用不同传输，不受该 Host USB 心跳缺陷影响；共用的时间采样新增无效值
  过滤和有限重读，不再发送错误的纪元级二次校时。需配套更新 Agent 的就绪等待修复，
  Sensor Board 不变。不包含时间回退或 UTC 保持问题；现有 ROS 工作空间需重新编译。
- SDK 源码修复：`DIBULI/Prism-agent@d6d32d048bc2ab853e6a5322adabf981abfe90a3`。

## 本次雷达待机更新

- 新增 ROS1/ROS2 `/prism/lidar/get_power` 与 `/prism/lidar/set_standby` 服务，
  支持 MID360/MID360S/XT32，USB 与 RK-local 使用统一 C++ 接口。
- 操作前停止全部采集；普通采集启停不变，唤醒不自动采集。超时必须回读确认。
- 同步 SDK 库并重新编译服务，版本保持 1.2.0。ROS 仍不提供离线数据集下载。
- 使用方法见[雷达待机/唤醒](../lidar-power.md)。

## 新增支持

- 同步刷新 Prism-SDK 1.2.0 依赖，配合 Agent/Viewer 的 USB 文件传输更新。
  **ROS 不提供离线数据集下载服务、话题或命令行**；SDK 只导出原始格式，bag 转换仍由 Viewer 完成。

- **接收机原生 GNSS / RTK**：分别发布 GGA 和 ADRNAV 定位结果，区分
  SINGLE、DGNSS、FLOAT、FIX；新增 `gnss/receiver`、`rtk/receiver`、`rtk/fix`。
- **精度信息**：输出接收机 ENU 标准差，转换为 NavSatFix 的米平方协方差；
  GGA 精度仅使用同一时刻的有效 GST。不伪造置信度百分比或把 HDOP 当作米级精度。
- **GNSS 接收诊断与原始文本**：新增 UART/NMEA 新鲜度、拒收/错误/溢出计数，
  以及带游标、会话和断档标记的 RMC/GGA/GST/GSV/GSA/ADRNAV 文本输出。
- **RTK-module 管理**：读取模块应用/引导程序版本、链路、启停状态、命令代次、
  错误、运行时间、SIM/网络、CORS 及传输计数。
- **CORS 配置和 RTK 启停**：账号/IP/端口/挂载点保存到 RK，由 Agent 在模块
  就绪后应用；模块自行访问 NTRIP。密码只写不读。启动需确认配置代次和发送
  实时 GGA 的许可，启停等待实际状态确认，不将普通 ACK 当作成功。
- **TimeSync 模式设置**：输入、PPS/NMEA 输出、RTK 三种模式；写操作需显式确认。
- **四相机统一自动曝光**：新增服务启用统一曝光时间，保留独立模拟增益，使用
  Agent/Sensor Board 的亮部保护；原有曝光/增益查询响应增加统一模式状态。
- **XT32**：可选择 `lidar_model: xt32`，保留逐点真实有符号时间偏移、通道
  `ring`、回波类型及厂商原始 `confidence` 字节。该字节不是精度百分比。
- **MID360 / MID360S**：保留 `line` 和 `line_valid`，按首尾跨度 / (N−1)
  恢复逐点时间；100 ms 聚合保留真实数据间隔，不填补丢包空隙。
- **RK-local ROS2**：纳入 Ubuntu 22.04/Humble、24.04/Jazzy ARM64 Docker
  构建与模拟测试，通过本机 Agent socket 连接，不需要 USB 透传。

## 行为变化与迁移

| 1.1.0 接口/行为 | 1.2.0 替代与变化 |
| --- | --- |
| `rtk/navigation`、`GetRtkNavigation`、`RtkNavigationStatus` | 删除；读取 `rtk/receiver` 或 `GetReceiverPosition`，来源为接收机 ADRNAV |
| `rtk/fix_raw`、`rtk/fix_smoothed` | 删除；改为 `rtk/fix`，不在 Adapter 中解算或平滑 |
| `rtk/status` 的 `RtkCorrectionStatus`、`GetRtkStatus` | 改为模块状态 `TimeSyncRtkStatus`、`GetRtkModuleStatus` |
| 输入 `rtk/corrections`、`ControlRtkCorrections` | 删除；改为 CORS 配置与模块 RTK 启停，不再向已移除的 RK 解算器喂数据 |
| raw/smoothed 双位置、RK 算法置信度、门控/滤波计数 | 删除；只提供接收机原生解类型和可用精度 |
| PointCloud2 固定 20 字节点结构 | 扩展为 28 字节，旧字段偏移不变，增加 `line`、`line_valid`、`ring`、`return_id`、`confidence`；按字段描述读取，勿硬编码旧步长 |
| 旧 SDK / Agent 1.1.0 | 不再作为本版运行目标；固定 SDK 1.2.0 提交 `970043c94131ab04f7e2f8de5267012785e4d1fd` |

仍保留四路压缩图像、曝光/增益元数据、IMU、设备与网络配置、采集启停、Wi-Fi、
显式校时和可选 rover RTCM3 输出。基本 PPS 有效性/脉宽仍保留，不公开 RK-PPS
quality 接口。原始录制文件不会被修改；本版不提供旧 raw/smoothed 消息兼容层。

## 时间、兼容性与限制

- 定位轮询目标 10 Hz，模块/接收诊断 1 Hz；新解速率取决于接收机，不能把轮询
  次数当作解算次数。超过 2 秒或断档的定位失效，不继续发布有效旧位置。
- ADRNAV 原始 epoch 是 GPST。`gps_utc_leap_seconds` 默认 `-1`，未知时 ROS
  UTC stamp 为 0；配置采集日期对应的正确闰秒差后再转换 UTC。GGA 使用有效的
  同步 PPS 日期。不会将主机收到数据的时间冒充接收机解算时间。
- CORS 保存、应用和连接成功是三个独立状态；RUNNING 不等于 FLOAT/FIX。
  RTK 启停与 TimeSync 模式写入会短暂暂停并恢复本节点的传感器采集。
- ROS1 Noetic；ROS2 Foxy、Humble、Jazzy、Kilted、Lyrical、Rolling 的 USB
  构建覆盖 Linux x86-64 与 ARM64。Foxy 仅保留旧环境构建支持。
- RK-local 仅支持 Linux ARM64 的 Humble/Jazzy；ROS1 仍为 USB 接入。
- SDK Linux 基线为 glibc 2.31；实际 ROS 运行依赖必须匹配对应发行版。
- 发布附件为源码包，**包含固定版本的 SDK 头文件与二进制库**，无需 Agent
  源码；不是通用预编译 ROS 节点，也不包含已导出的 Docker 镜像。
- CI/服务器验证为编译、消息序列化、公共回归和模拟 Agent 通信，不代表新的
  设备端相机/雷达/CORS 实测。本次不刷固件、不设置设备时间或自动启动 CORS。
