# Prism ROS Adapter v1.2.0

## Independent sensor streams refresh

- Publish each complete camera image from partial sets; missing/corrupt slots
  produce no image, and ACK retirement remains bounded and exactly once.
- Missing camera/IMU/LiDAR/GNSS data or a read timeout warns without stopping
  other streams. A shared transport disconnect remains a real session failure.
- Do not block LiDAR solely because another configured timestamp reference is
  absent; synchronized-timestamp validation still applies to available references.
- Refresh Host and RK-local SDK together; RK-local is PIC-compatible. ROS topics
  and services are unchanged. No offline dataset-download feature is added.

Aligned with **Prism-SDK 1.2.0 / Runtime API 18**, Agent 1.2.0 and Sensor Board
0.4.27. Rebuild ROS messages/services and all dependent nodes: this is not a
drop-in replacement for the 1.1.0 generated interfaces.

## SDK maintenance refresh

- Pin Host and RK-local SDK headers/libraries to Prism-SDK commit
  `a35c25fad9f8fc9b8a0c39badd10b0d519502cb5`; rebuild USB and RK-local consumers.
- The SDK adds `startSensorBoardUpdate()` and `sensorBoardUpdateStatus()` for
  Agent-managed Sensor Board maintenance. This dependency refresh does not expose
  firmware upgrade services/topics in ROS or change existing ROS interfaces.
- Retain the calibration keepalive and time-sample validation fixes. Distribution
  version remains 1.2.0, Runtime API remains 18, and Linux glibc baseline remains 2.31.
- Release archives include the refreshed SDK. Rebuild installed ROS workspaces
  or Docker images to use it; existing binaries do not update automatically.
- Matched Agent: `3380718`; SDK maintenance implementation: `21c09ae`.
  No offline dataset download functionality or automatic device updates are added.

## USB calibration keepalive fix

- Refresh the pinned Host SDK so explicit idle clock calibration preserves its
  USB keepalive worker on success and exception. Starting acquisition afterward
  no longer requires reconnecting solely to recover that worker.
- Calibration errors remain visible; capture watchdogs, ROS interfaces and ABI
  are unchanged. RK-local/Web use a different transport and are not affected by
  this USB-specific defect. This does not add offline dataset download support.
- Fix source: `DIBULI/Prism-agent@d6d32d048bc2ab853e6a5322adabf981abfe90a3`.
  Also reject unavailable/discontinuous calibration samples and wait read-only
  for canonical mapping readiness; no epoch-sized verification correction.
  Deploy the matched Agent readiness fix; Sensor Board is unchanged. UTC retention
  and later clock rollback remain outside scope. Rebuild ROS workspaces against
  the refreshed SDK package. No ROS messages, topics or services change here.

## LiDAR hardware power refresh

- Add `/prism/lidar/get_power` and `/prism/lidar/set_standby` for ROS1/ROS2,
  with matching USB/RK-local C++ APIs for MID360/MID360S/XT32.
- Stop all streams first. Ordinary capture start/stop is unchanged; wake does
  not start capture. Check success/readback; query after an unconfirmed timeout.
- Refresh the matched SDK libraries and rebuild generated services. Version
  remains 1.2.0. ROS still has no offline dataset download functionality.
- See [LiDAR power controls](../lidar-power.md).

## Added

- Refresh the pinned SDK 1.2.0 binaries alongside Agent/Viewer USB file transfer.
  ROS remains a live acquisition/control adapter: **no offline dataset download
  service, topic or CLI**. SDK exports raw files only; bag conversion stays in Viewer.

- Separate receiver-native GGA and ADRNAV positions, SINGLE/DGNSS/FLOAT/FIX,
  epoch/freshness, receiver ENU sigma and NavSatFix covariance. GGA uses only
  epoch-matched GST; no invented confidence percentage or DOP-as-covariance.
- GNSS UART/NMEA reception diagnostics and cursor/session/gap-preserving text
  observations, including available RMC/GGA/GST/GSV/GSA/ADRNAV sentences.
- RTK-module application/bootloader versions, control state/error/generation,
  uptime, SIM/network/CORS state and transfer/drop counters.
- CORS configuration persisted by Agent on RK, applied when the module is
  ready. Password is write-only. RTK start binds explicit GGA permission to
  the saved account generation; start/stop verify terminal receiver state.
- TimeSync input/output/RTK selection; four-camera unified automatic exposure
  and highlight protection with independent gains.
- XT32 model selection and explicit point timing, ring, return and vendor byte;
  MID360/MID360S line validity and first-to-last-span/(N−1) point timing.
- RK-local ROS2 Docker builds for Ubuntu 22.04/Humble and 24.04/Jazzy ARM64,
  using Agent's local socket with no USB passthrough.

## Removed / breaking changes

- Removed `RtkNavigationStatus`, `GetRtkNavigation`, `rtk/navigation`,
  `rtk/fix_raw`, `rtk/fix_smoothed` and RK raw/smoothed solver confidence/filter
  fields. Use `ReceiverPosition`, `GetReceiverPosition`, `rtk/receiver` and
  `rtk/fix`; the adapter does not solve or smooth RTK.
- Removed Host `rtk/corrections`, `ControlRtkCorrections`, `GetRtkStatus` and
  `RtkCorrectionStatus`. The `rtk/status` path now uses `TimeSyncRtkStatus`;
  `rtk/get_status` uses `GetRtkModuleStatus`. Configure/control the external
  module's NTRIP client instead of feeding the retired RK solver.
- PointCloud2 point stride is now **28 bytes**, not 20; original field offsets
  remain unchanged. Added `line`, `line_valid`, `ring`, `return_id`, `confidence`.
  Read fields/point_step instead of hardcoding the old layout.
- Exposure responses add `unified_automatic`; old SDK/Agent 1.1.0 and old
  raw/smoothed ROS messages are not compatibility targets.

Camera/IMU, device/network configuration, acquisition control, Wi-Fi, explicit
clock synchronization and optional receiver RTCM3 output remain supported.
Basic PPS validity/width remain; RK-PPS quality is not exposed.

## Packaging, timing and limits

- USB CI matrix: Noetic, Foxy, Humble, Jazzy, Kilted, Lyrical, Rolling on Linux
  x86-64/ARM64; Foxy is retained only for legacy deployment builds. RK-local:
  Humble/Jazzy ARM64 only; ROS1 remains USB-only.
- SDK pinned to `a35c25fad9f8fc9b8a0c39badd10b0d519502cb5`, glibc baseline 2.31.
  Release source archive includes its matching headers and binary libraries;
  no Agent implementation source or universal precompiled ROS node is shipped.
- Navigation poll target 10 Hz, module/reception status 1 Hz; actual new-fix
  rate depends on the receiver. Stale/invalid solutions are not valid fixes.
- ADRNAV epoch is GPST. UTC NavSatFix stamps require an explicitly verified
  `gps_utc_leap_seconds`; default -1 leaves UTC stamp zero/unknown. GGA uses a
  live synchronized PPS date. Host receipt time is never substituted.
- Saved/applied/connected CORS states are distinct; RUNNING is not a FIX.
  RTK controls and TimeSync mode writes briefly pause/restore active streams.
- Tests cover software builds, serialization, regression and mock Agent
  communication, not new physical device/CORS qualification. No firmware or
  clock is updated and CORS is not started automatically by this release.
