Prism ROS Adapter 1.3.0

- Pin published Prism SDK 1.3.0 d4ac1e91c09137b21501fcc5a3a47db218021ee8,
  including matching headers and Linux x64/ARM64 runtime libraries.
- Include the validated 415M RAW12 shared-trigger header helpers and their
  regression test. Transport ABI19/binaries and ROS JPEG/metadata topics remain
  unchanged; this does not add the Viewer RAW grouped-display feature to ROS.
- Include required license files in RK-local container builds. Network smoke
  cases use independent ROS contexts and discover subscriptions/services before
  starting the positive stream test; authentication and stream checks remain.
- ROS1/ROS2 host nodes select USB or network at runtime. Dedicated network
  launch files accept a numeric host and optional port (default 7443).
- Read the Web login password from a named environment variable, not a ROS
  parameter/YAML value. Plaintext TCP is for trusted LANs only; no old TLS pairing.
- Reject invalid endpoints and mismatched optional serial before capture.
  No automatic USB fallback. RK-local remains a separate ARM64 build.
- Preserve existing topics and sensor health warnings; USB remains supported.
- Fix inherited shared-loop starvation: drain a bounded SDK receive batch before
  navigation queries and schedule subsequent polls from query completion.
- Bound camera dispatch to eight sets and expose queue depth/peak diagnostics.
- ROS2 bounds unacknowledged publication bursts using worker-only DDS ACK checks
  (one image or64boardIMU samples,100ms timeout). Camera publisher history8,
  IMU history unchanged512. Timeouts remain visible; ACK is not disk completion.
- Older ROS2 APIs such as Foxy lack the public DDS wait operation. Those builds
  retain bounded queues and explicitly report dds_ack_supported=false/WARN;
  they do not claim the newer acknowledgment protection.
- Offline: Linux/macOS common tests, Linux ROS2 Jazzy build and delayed-navigation
  NET/4 loopback passed. ROS1 runtime has not been tested.
