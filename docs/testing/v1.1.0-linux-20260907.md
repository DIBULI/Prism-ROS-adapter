## Limits of the device validation

The connected device had **no fresh GNSS input**: 0 satellites, no valid PPS,
external time not synchronized, and NMEA age over two hours. Therefore:

- Live RTCM output control was verified, but **0 actual rover bytes** arrived.
- Real GPS coordinates, live RTK FLOAT/FIX, raw/smoothed accuracy and end-to-end
  correction decoding were **not** verified on this device in this run.
- RTCM byte preservation was checked through ROS serialization, not through a
  live receiver/base station.
- The GNSS-lock host-time guard is implemented but was not exercised by sending
  a confirmed clock request to real hardware; tests never alter the clock.
- LiDAR aggregation regression tests passed; live LiDAR capture was not started.

Repeat the hardware test after reconnecting a working GNSS receiver and supplying
current RTCM base corrections. Do not interpret status refresh rate as new RTK
solution rate; inspect the raw and smoothed solution epochs.
